# Акватель — демонстрационный прототип

Интернет-магазин воды и панель управления для презентации модернизации a-tel.ru. Реализованы этапы 1–9 из `master.md`. **Это демонстрационная версия: реальные заявки, доставка и платежи не выполняются.** Админка открыта без авторизации. Вводите только вымышленные данные.

## Установка и запуск

Нужны Node.js **22.13+** и npm.

```sh
npm ci
npm run dev
```

Откройте http://localhost:3000. Для презентации рекомендуется production-сборка:

```sh
npm run build
npm start
```

Первая сборка загружает Inter через `next/font/google` и требует доступ к Google Fonts. Изображения товаров находятся в `public/images/` и обслуживаются локально.

## Публикация на GitHub Pages

В репозитории откройте **Settings → Pages → Build and deployment → Source** и выберите **GitHub Actions**. Режим `Deploy from a branch → main → / (root)` публикует исходники и показывает README вместо Next.js-приложения.

После отправки изменений в `main` workflow `.github/workflows/pages.yml` установит зависимости, соберёт статическую версию в `out/` и опубликует её. Состояние доступно во вкладке **Actions → Deploy to GitHub Pages**; workflow можно запустить вручную через **Run workflow**. Адрес: https://gnj333.github.io/a-tel/.

Проверить такую сборку локально:

```sh
GITHUB_PAGES=true npm run build
```

По умолчанию используется префикс `/a-tel`; workflow получает актуальный путь из настроек Pages через `PAGES_BASE_PATH`. Для собственного домена без префикса задайте `PAGES_BASE_PATH=""`. Папка `out/` содержит готовый сайт и не коммитится. Обычные `npm run dev` и `npm run build && npm start` продолжают работать без префикса.

На Pages карточки открываются через `/catalog/view/?slug=…`, `/admin/products/view/?id=…` и `/admin/orders/view/?id=…`. Это позволяет открывать и перезагружать карточки новых товаров и заказов из localStorage без сервера и повторного деплоя. Страницы исходных товаров и заказов по прежним адресам также включены в сборку.

## Маршруты

| Адрес                  | Возможности                                                                 |
| ---------------------- | --------------------------------------------------------------------------- |
| `/`                    | Главная, выбор воды, сохранение и повторение набора, категории, FAQ         |
| `/catalog`             | Поиск, категории, объём, диапазон цены, сортировка, покупка                 |
| `/catalog/[slug]`      | Фото с увеличением, характеристики, количество, покупка, похожие товары     |
| `/cart`                | Изменение количества, удаление, проверка доступности, предварительная сумма |
| `/checkout`            | Валидация формы, создание демо-заказа, экран подтверждения                  |
| `/delivery`, `/about`  | Информация о компании и доставке с источниками                              |
| `/account`             | Информационная страница; авторизация отсутствует                            |
| `/admin`               | Показатели, график за 7/30/90 дней, последние заказы, популярные товары     |
| `/admin/products`      | Поиск, категории, статусы публикации, архивация с подтверждением            |
| `/admin/products/new`  | Создание товара, валидация, локальная загрузка фото                         |
| `/admin/products/[id]` | Редактирование товара; изменения видны в магазине                           |
| `/admin/orders`        | Фильтры номера, статуса и дат                                               |
| `/admin/orders/[id]`   | Состав заказа, вымышленные контакты, смена статуса и история                |

Примеры карточек: `/catalog/akvatel-19`, `/catalog/akvatel-light-19`, `/catalog/ecotronic-k12-te-white`. Редактирование первой воды: `/admin/products/water-akvatel-19`.

Каталог сохраняет фильтры в URL, например `/catalog?category=pompy&min=350&max=700&sort=price-desc`. Поддержаны `q`, `category`, `volume=19|other`, `min`, `max`, `sort=price-asc|price-desc|name-asc|name-desc` и Back/Forward. Черновые и архивные товары скрыты от покупателя.

Форма оформления автоматически сохраняет все поля в localStorage (`akvatel-demo-checkout-form-v1`), включая незавершённый ввод. Данные восстанавливаются после перезагрузки, возврата на страницу и при следующем заказе. В истории заказов контакты и адрес по-прежнему заменяются вымышленными данными.

## Демонстрационные данные и сброс

Исходный набор: **8 товаров в 5 категориях** и **48 вымышленных заказов** за последние 90 дней, с шестью статусами. Даты заказов создаются при инициализации и обновляются при сбросе. Показатели Dashboard рассчитываются из этих заказов; это демонстрационная аналитика.

Интерфейс магазина и админки использует обычные названия действий и заказов без пометок демо-режима. Сброс из интерфейса убран; mock-хранилище и замена контактов в истории заказов сохранены. При обновлении прежние подписи заказов автоматически заменяются, состав, цены и история статусов сохраняются.

Для сброса удалите `akvatel-demo-data-v1`, `akvatel-demo-cart-v1` и `akvatel-demo-checkout-form-v1` в DevTools → Application → Local Storage и перезагрузите страницу. Не используйте `localStorage.clear()`, если на том же origin есть другие приложения.

## Сценарий презентации — 5–7 минут

1. Выполните сброс и откройте главную. Покажите выбор количества и категории.
2. Перейдите в каталог, выберите воду 19 л и сортировку цены, откройте «Акватель».
3. Покажите увеличение фото, характеристики и условия обмена тары. Добавьте две бутыли.
4. Откройте корзину, измените количество. Перейдите к оформлению.
5. Заполните форму вымышленными данными и выберите текущую или будущую дату. Отметьте сохранение состава и оформите демо-заказ. Покажите экран подтверждения.
6. Откройте `/admin`, переключите 7/30/90 дней. В заказах найдите номер с экрана подтверждения.
7. Откройте заказ, смените статус на «Подтверждён», сохраните и обновите страницу. Покажите историю.
8. В товарах измените цену «Акватель» с 480 на 515 ₽. Откройте каталог на **том же origin**: новая цена доступна сразу и после обновления.
9. Оформите ещё один заказ и покажите его в админке. Старый заказ хранит прежнюю цену, новый — 515 ₽.
10. Вернитесь на главную и покажите повторение сохранённого набора. После презентации выполните сброс.

## Mock-хранилище и архитектура

- `src/app/(store)` и `src/app/(admin)` — отдельные оболочки покупателя и менеджера.
- `src/components/ui`, `shared`, `product` — общие компоненты; React/Radix, Tailwind и Lucide.
- `src/domain/models.ts` — типизированные товары, категории, корзина, заказ и история статусов.
- `src/data/mock/seed.ts` — исходный ассортимент; `demo-orders.ts` — вымышленные заказы.
- `src/data/mock/store.ts` — общий Zustand store товаров, категорий и заказов с persist; ключ `akvatel-demo-data-v1`, версия схемы 5.
- `src/features/cart/store.ts` — корзина и отдельный сохранённый набор; ключ `akvatel-demo-cart-v1`, версия 1.
- `src/services/repository.ts` — асинхронный контракт `ShopRepository`; `mock-repository.ts` — клиентский адаптер.
- `src/features/admin`, `catalog`, `product`, `cart`, `checkout`, `demo` — прикладные сценарии.

Данные восстанавливаются после монтирования (`skipHydration`); до этого показаны Skeleton. Сервер начинает с seed. Клиентские страницы подписаны на общий store, поэтому правки админки видны в каталоге, карточке и корзине. Изменения общего репозитория синхронизируются между вкладками через событие `storage`. Корзину и оформление демонстрируйте в одной вкладке. Хранение ограничено одним браузером и origin: `localhost`, IP-адрес, другой порт и другой протокол — разные среды.

Заказ хранит снимок названия, цены и количества: последующее редактирование/архивация товара не меняет историю. Статусы: новый, подтверждён, в сборке, в доставке, выполнен, отменён. Время отображается по Тюмени (`Asia/Yekaterinburg`). При ошибке сохранения заказа или правки товара изменения в памяти откатываются; форма сообщает об ошибке.

Форма checkout использует React Hook Form и Zod. Имя, телефон, адрес и комментарий формы **не записываются** в историю: перед сохранением они заменяются вымышленными значениями. Сохраняются товары, количество и желаемая дата. Реальные данные вводить не следует. Экран подтверждения существует до ухода/перезагрузки страницы; сам заказ остаётся в админке.

Количество ограничено 99 единицами продажи. Вода 5 л продаётся упаковкой 4 × 5 л за 480 ₽, количество означает упаковки. Суммы рассчитываются через целые копейки. Доставка и дополнительная тара не рассчитываются автоматически, итог помечен как предварительный. Сохранённый набор хранит только товары и количество, восстанавливает доступные позиции по текущим ценам без удвоения.

## Проверки

ESLint проверяет Next.js, React и TypeScript; Prettier отвечает за единый формат кода. Конфигурации согласованы через `eslint-config-prettier`. Команды запускаются из корня проекта:

```sh
npm run format:check
npm run typecheck
npm run lint
npm test
npm run build
```

Для форматирования всего проекта выполните `npm run format`, для автоматического исправления замечаний ESLint — `npm run lint:fix`. Сборки, отчёты тестов и генерируемые файлы исключены из проверок. `lint` завершается с ошибкой также при предупреждениях.

Для VS Code добавлены рекомендации расширений ESLint и Prettier и настройки форматирования при сохранении. Установите рекомендованные расширения, чтобы включить их в редакторе.

В WebStorm в Settings → Languages & Frameworks → TypeScript используйте пакет `node_modules/typescript`, включите TypeScript Language Service и Enable service-powered type engine. Это согласует определение типов в IDE с компилятором проекта, в том числе для типов React и Playwright. После изменения настроек перезапустите TypeScript Language Service и повторите анализ перед коммитом.

Браузерные проверки Chromium:

```sh
npx playwright install chromium
npm run test:e2e
```

`test:e2e` собирает production-версию и запускает её на порту **3100**; порт должен быть свободен. Если Chrome уже установлен, вместо загрузки Chromium можно указать путь:

```sh
PLAYWRIGHT_CHROME_PATH=/usr/bin/google-chrome npm run test:e2e
```

После существующей сборки: `npx playwright test`. HTML-отчёт: `npx playwright show-report`. Скриншоты — `test-results/presentation/`, трассировки сбоев — `test-results/`. Эти файлы игнорируются Git. Браузерные тесты используют изолированные контексты и не изменяют данные вашей презентационной вкладки.

Покрытие: полный путь покупки, валидация формы, связь checkout с админкой, редактирование цены, история статусов и сохранность снимка заказа, перезагрузка, сброс и отмена, пустые/недоступные состояния, основные маршруты, изображения и ошибки браузера. Проверяемые ширины: **375, 390, 768, 1024, 1440 px**.

Источники коммерческих данных указаны в `source` у товаров в `src/data/mock/seed.ts`. Ограничения прототипа описаны ниже.

## Границы прототипа и внедрение

Цены и условия — сохранённые снимки a-tel.ru от 26–28.10.2026; они не являются офертой и не обновляются автоматически. Подтверждённых отзывов, акций и сертификатов нет. SEO-метаданные карточек используют seed; локальные правки меняют клиентский экран. Индексация отключена через `robots` в метаданных.

Отсутствуют backend, база данных, учёт остатков, настоящие покупатели, оплата, расчёт доставки и авторизация. Фото новых товаров хранятся в localStorage как data URL, до 1 МБ на файл, в пределах квоты браузера. Хранилище не обеспечивает транзакции между вкладками и одновременную работу менеджеров; удаление данных браузера удаляет все изменения.

Для реального запуска потребуются:

- API и БД с серверной валидацией, транзакциями и резервными копиями; адаптер вместо `mockRepository`.
- Авторизация менеджеров, роли, защита маршрутов и журнал действий.
- Согласованные ассортимент, цены, наличие, тарифы доставки и условия оборотной тары.
- Интеграции с учётом заказов/CRM, логистикой, уведомлениями и платёжной системой.
- Защищённая обработка персональных данных, согласованные юридические документы.
- Серверное хранение изображений, мониторинг, production-хостинг и проверка на целевых устройствах.
